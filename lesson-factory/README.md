# lesson-factory

초등 수업 자료(지도안 · 활동지 · 슬라이드) 제작 파이프라인.

> **현재 상태: P1 (세안 생성) 진행 중.** 아직 LLM 을 호출하지 않는다.
> 스키마 · 성취기준 DB · 기계 검증기 · **세안 렌더러** · 프롬프트 2종까지 만들어졌고,
> 오케스트레이터는 P2에서 붙인다.

---

## 왜 만드는가

수업 자료를 AI로 만들 때 반복되는 실패가 있다 — **활동지와 슬라이드가 지도안 없이 따로 만들어져
서로 맞는지 확인할 방법이 없는 것.** (실과 4단원에서 실제로 발생: *"지도안 파일 부재 →
성취기준 기반 재구성 → 원본 지도안과 대조 필요"*)

이 파이프라인은 **지도안을 유일한 진실로 고정**하고, 활동지·슬라이드가 거기서 파생되며,
일치 여부를 **기계가** 검사한다.

## 설계 원칙 4개

1. **에이전트는 LLM 호출 1회** — JSON 입력, JSON 출력. 모델이 다른 모델을 호출하지 않는다.
   위계는 코드의 상태기계가 만든다.
2. **기계로 검사 가능한 것은 LLM에게 묻지 않는다** — 실패하면 LLM 검수를 호출조차 하지 않는다.
3. **검수자는 제작자의 사고 과정을 보지 않는다** — 산출물과 루브릭만. (앵커링 방지)
4. **하드 제약은 프롬프트가 아니라 코드에.**

## 실물 조사로 배운 것 (2026-07-28)

스키마를 짓기 전에 구글드라이브의 완성 자료를 열어 보고 설계를 고쳤다.

| 발견 | 반영 |
|---|---|
| 지도안은 이미 있다 — `약안/` 소단원별 md 7개가 48차시를 덮는다 | 스키마를 **약안 표의 인코딩**으로 재설계. 새로 발명하지 않았다 |
| 고정 슬라이드 순서가 실제로는 안 지켜진다 (차시마다 다른 서사) | `slides[].kind` **개방형**으로. 기계 검사는 `role` 로만 한다 |
| 케이건 구조명이 슬라이드에 없다. 계획에만 있다 | 구조 검증을 **지도안↔활동지**에서 한다. 덱에는 요구하지 않는다 |
| 계획은 `부채모양 뽑기`, 산출물은 `직소` — 실제 드리프트 사례 | **드리프트 검출 테스트**를 P0에 넣었다 |
| 케이건 구조가 9종보다 많다 (템플릿이 9종일 뿐) | 19종 enum + `has_template` 플래그 |
| 활동지 항목이 번호가 아니라 이름표 (`OPTION_A`) | `W1` 형식 폐기 |
| 정답은 항상 다음 슬라이드 (노트에 "정답 선노출 금지" 명시) | 검사 유지 — 실물과 맞았다 |
| 시간 배분 합계 40분 | 검사 유지 — 실물과 맞았다 |

## "즐겁고 협동적이고 참여도 높게"를 어떻게 보장하는가

프롬프트로 부탁하지 않는다. **케이건 협동학습 구조를 스키마로 강제**한다.

- 전개 활동은 19종 중 하나를 반드시 고른다 (스키마)
- 서로 다른 구조를 2종 이상 쓴다 (기계 검증, 아니면 경고)
- **고른 구조가 요구하는 활동지 칸이 실제로 있는지 검사한다** — 이름만 붙은 협동을 잡아낸다
  예: `생각-쓰기-짝-비교`는 `개인쓰기` 칸이 없으면 비교할 산출물이 없어 성립하지 않는다

## 약안이 아니라 세안 (2026-07-29 방향 전환)

담임 판정: **"약안 말고 세안으로 짜줘. 약안은 게임 내용을 모르겠더라."**

실측으로 확인했다. 같은 1차시 게임을 두 문서가 이렇게 적는다.

| | 게임 설명 |
|---|---|
| 약안 | `'유교 문화 축제에서 동생 찾기' 미션 — 단원 그림 단서로 추측` (**26자**) |
| 세안 | 동생 이름 **태웅이** · 단서는 **가족 4명의 말** · 답은 **어느 체험관** ·<br>절차 ①문장틀로 쓰기 → ②시계 방향으로 넘기기 → ③친구 답에 더하기 |

약안에는 T/S 발화가 **0줄**, 평가·판서·유의점이 전부 없다. 세안에는 T 9줄·S 7줄이 있다.
게다가 **시간이 안 맞는다** — 약안 4+12+12+8=36분, 세안 5+12+15+8=40분.
`check_minutes_sum` 이 약안 쪽을 잡는다. 검사가 실물에서 작동한다는 증거다.

그래서 지도안 스키마를 **세안 7개 절의 인코딩**으로 다시 짰다.

| 세안의 절 | 스키마 |
|---|---|
| 머리표 10칸 | `meta.lesson_title` · `meta.teacher_guide_pages` · `meta.sub_unit_period` · `teaching_model` · `social_skill` |
| 본시 과정 표 5열 | `activities[].stage_label` · `learning_content` · **`blocks[]`** · `minutes` · `materials`+`cautions` |
| 게임 | **`activities[].game`** |
| 평가 계획 | `assessment.observations[]` — `scale` 로 상/중/하 · 도달3 둘 다 |
| 판서 계획 | **입력하지 않는다.** 본문에서 파생 (`render/sean.py::board_plan`) |
| 지도상의 유의점 | `guidance_notes[]` |

### 게임을 굴릴 수 있는가 — 기계가 보는 것

| 검사 | 잡는 것 |
|---|---|
| `game_runnable` | 절차만 있고 문장틀도 교사 대사도 없음 → 게임이 아니라 게임 이름 |
| `game_materials` | 게임 준비물이 자료 목록에 없음 → **실물 세안이 실제로 놓쳤다** (단서 종이) |
| `competition_policy` | '순위 금지'라 써 놓고 순위를 공개하는 게임 |
| `dialogue` | 교사 발화가 한 줄도 없음 / **절반만 세안** |
| `slide_range` | 슬라이드 배정이 겹치거나 빔 |

`scoring` 과 `win_condition` 은 **일부러 선택**이다. 실물 활동1이 비워 두었고
(*※정답 찾기보다 "그림 속 유교 문화 요소 발견"이 목적*), 억지로 요구하면 확산적 활동이
정답 맞히기로 변질된다. 대신 **읽고 굴릴 수 있는가**는 LLM 검수 R8 이 본다.

## 교과서 대체 정책

**학습목표 도달이 유일한 기준이다.** 교과서 활동을 그대로 쓸 의무는 없고,
더 즐겁고 참여도 높은 활동으로 대체할 수 있다. 대신 학습목표 연결을 조인다.

| 요구사항 | 강제 방법 |
|---|---|
| 모든 활동은 최소 1개 학습목표에 연결 | 스키마 |
| 모든 학습목표는 최소 1개 활동이 다룸 | 기계 검증 (역방향) |
| 대체 시 `replaces` · `rationale` 필수 | 스키마 + 기계 검증 |
| 대체가 원래만큼 목표에 도달시키는가 | LLM 검수 R6 |

## 테스트가 확인하는 것

- 스키마 4종이 유효한 JSON Schema인가, 정상 픽스처가 통과하는가
- **불량 픽스처가 실제로 걸리는가** — 학습목표 없는 활동, 케이건 구조 없는 전개, 근거 없는 대체,
  번호식 활동지 id, OX 근거 누락, 수정안 없는 불합격 판정, 정답 선노출, 팔레트 불일치
- **계약 파일들끼리 어긋나지 않는가** — 스키마 enum ↔ `kagan_structures.json`,
  구조가 요구하는 역할 ↔ 활동지 role enum, era enum ↔ 팔레트 파일
- **드리프트가 검출되는가** — 계획한 협동 구조를 활동지가 지탱하지 않으면 잡힌다

> 계약 파일이 여러 개로 갈라져 있으면 하나만 고치고 나머지를 잊는다.
> 그러면 지도안은 통과하는데 활동지 템플릿이 없는 사태가 난다. 그래서 파일 간 정합도 테스트한다.

## 기계 검사의 한계 — 명시적으로 기록해 둠

`tests/test_checks.py::test_existing_but_wrong_standard_is_NOT_caught`

성취기준 `6사03-02`(인권)는 **실재하므로 DB 검사를 통과한다.** 조선 후기 수업에 전혀 맞지 않는데도
기계는 잡지 못한다. **코드가 실재하는가**와 **그 코드가 이 수업에 맞는가**는 다른 질문이고,
후자는 LLM 검수(R1·R7)의 몫이다. 이 경계를 흐리지 않기 위해 실패가 아니라 테스트로 남겼다.

## 골든 픽스처 — 실물을 넣어 본 결과

`tests/fixtures/실과-5-2-5단원-4차시.*` 는 실제 완성 자료(5단원 4차시 「친환경 구조물 설계
스튜디오」)를 스키마로 옮긴 것이다. 활동 7개 · 40분 배분 · 활동지 블록 9개 · 슬라이드 26장.
출처와 신뢰도는 `tests/fixtures/README.md` 에 적어 두었다.

옮기면서 스키마를 다섯 군데 고쳤다.

| 발견 | 조치 |
|---|---|
| `짝 코칭` 이 enum 에 없었다 | 구조 추가 — 짝 점검(정답 확인)과 다른 구조다 |
| 역할에 `짝피드백` `산출물` `자기점검` `수정근거` 가 없었다 | 4종 추가. 수정 전/후/이유는 이 단원 평가의 중심이다 |
| 분석표는 `모둠 합의`, 템플릿은 `모두미 협의` | `aliases` 필드 추가 |
| 하나의 구조가 여러 활동에 걸쳐 실행된다 | 역할 검사를 같은 구조를 쓰는 활동들의 **합집합**으로 |
| 사회 수업에 실과 성취기준을 붙여도 안 걸렸다 | 과목 대조 검사 추가 (NCIC 과목명 별칭 포함) |

남은 미담김 3가지(슬라이드 복수 역할 · 분 단위보다 잘게 쪼갠 시간 · 의도적 결함 예시)는
수업의 질을 좌우하지 않는다고 보고 스키마를 늘리지 않았다. 근거는 픽스처 README 에 있다.

## 세안 골든 픽스처 — 왕복 확인
